# Реальная проверка и сдача через учебную «1С:Предприятие»

Проект содержит исходники **XML + BSL**. Синтаксис проверяет GitHub Actions, но только установленная **учебная платформа 1С 8.3** может подтвердить загрузку конфигурации, исполнение модулей и получение `.dt`.

## Системные требования

Linux x86_64, официальный учебный исполняемый файл `1cv8t`, `bash`, `coreutils` и `xvfb-run` для работы без графического окружения. XML подготовлен в формате платформы 8.3.27, совместимость со старыми версиями не гарантируется.

## Проверка импорта в чистую базу

```bash
export ONEC_TRAINING_BIN=/полный/путь/к/1cv8t
bash scripts/check-config-in-onec.sh
```

Скрипт создаёт временную базу через `CREATEINFOBASE`, загружает иерархический XML с помощью `/LoadConfigFromFiles`, выполняет `/UpdateDBCfg`, `/CheckConfig` и `/DumpCfg`, затем удаляет временную базу. При ошибке любого этапа проверка останавливается. Для каждого этапа проверяется и код возврата процесса, и результат штатного файла **`/DumpResult`**: только `0` считается успешным.

**Эта интеграционная проверка подготовлена, но ещё не выполнялась в реальной учебной платформе.** Пока она не пройдена, считать конфигурацию запускаемой нельзя.

## Создание постоянной учебной базы

```bash
bash scripts/check-config-in-onec.sh --keep-db "$HOME/1c-warehouse-lab"
```

Откройте полученную базу в режиме **1С:Предприятие**. В меню **Сервис → Проверка лабораторной** нажмите «Запустить проверки». Обработка создаёт учебные товары, склады и накладные, проверяет приход, запрет расхода ниже минимума, независимость складов, повтор товара и все четыре вычислительные задачи. **Тест создаёт данные**: не запускайте его на рабочей базе.

Проверьте формы, печать и Excel-выгрузку обеих накладных, четыре отчёта СКД и сервис **Анализ складских данных**. Затем при необходимости добавьте дополнительные демонстрационные данные для преподавателя.

## Выгрузка итогового файла `.dt`

```bash
bash scripts/dump-demo-dt.sh "$HOME/1c-warehouse-lab"
```

Команда вызовет `/DumpIB` и создаст `artifacts/warehouse.dt`. В нём окажутся **и конфигурация, и данные**. Рекомендуется восстановить этот `.dt` в отдельную чистую информационную базу и повторить проверку.

Файл `.dt` потенциально содержит персональные данные; Git LFS их **не шифрует**. Загружайте его в репозиторий только после проверки содержимого.

```bash
git lfs install
git add artifacts/warehouse.dt
git commit -m "artifacts: add verified educational 1C laboratory database"
git push
```

## Приёмочные критерии

1. Реальный импорт XML и `/CheckConfig` успешны.
2. Можно открыть все четыре справочника, обе накладные и четыре обработки задач.
3. Расход 9000 при остатке 10000 и минимуме 1000 разрешён; расход 9001 не сохраняется и не проводится.
4. Учитываются отдельные склады и повтор товара в строках.
5. Все четыре отчёта читают регистры и показывают табличные, линейные и диаграммные данные.
6. Печатные формы и экспорт XLSX доступны из обеих накладных.
7. Встроенный `АнализДанных` формирует результат для выбранного склада.
8. Контрольные ответы задач: 5; 10; 600; 68800.
9. Итоговый `.dt` реально восстановлен и открывается в учебной 1С.
