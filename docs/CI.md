# Проверка .dt на учебной платформе «1С:Предприятие»

## Что требуется от CI

**Единственная обязательная проверка — настоящая проверка `artifacts/warehouse.dt` штатной учебной платформой `1cv8t`.** Никакой успешный `nix flake check`, тест mock-скрипта или проверка Markdown не заменяют проверку 1С.

`.github/workflows/ci.yml` запускается после push в `main` и вручную. Сначала короткий preflight на GitHub-hosted runner требует наличие `.dt` и включённую настройку `ONEC_TRAINING_CI=true`. Если что-то не настроено, CI **красный**, а не «успешно пропущенный». Затем job обязательно запускается на доверенном self-hosted Linux x86_64 runner с учебной 1С.

### Что делает учебная 1С

1. Проверяет, что файл `.dt` существует, не пуст и не является текстовым Git LFS pointer.
2. **`/RestoreIB`** — загружает `.dt` в **новую одноразовую** файловую информационную базу. Если база не восстанавливается — ошибка.
3. **`/CheckConfig`** — проверяет логическую целостность, некорректные ссылки, модули для тонкого и толстого управляемого клиента и сервера, наличие обработчиков и расширенную проверку модулей.
4. **`/IBCheckAndRepair -LogAndRefsIntegrity -TestOnly`** — тестирует логическую и ссылочную целостность без изменения данных.
5. **`/DumpCfg` и `/DumpDBCfg`** — убеждается, что конфигурация и конфигурация базы данных могут выгружаться в непустые файлы `.cf`.

Неуспех любого этапа приводит к **failed**. Выходные журналы показываются в логе workflow. По завершении временная база удаляется.

**Ограничение:** этот CI проверяет восстановление и статическую техническую корректность в Конфигураторе. Он ещё **не проверяет запуск пользовательского сеанса ENTERPRISE** и выполнение складских операций. Для подтверждения реального пользовательского запуска нужен отдельный smoke-тест с автоматическим завершением сеанса (например, внешняя обработка `.epf`); без такого теста выдавать «проверено, что всё запускается» нельзя.

## Настройка один раз

1. Установить **официальную учебную версию 1С** для **Linux x86_64** на доверенную машину. Убедиться, что исполняемый файл `1cv8t` поддерживает нужные команды пакетного Конфигуратора. Эта программа не входит в nixpkgs и устанавливается отдельно из официального дистрибутива.
2. Зарегистрировать на этой машине GitHub Actions **self-hosted runner** с меткой **`onec-training`**. Установить `git-lfs`, `bash`, `timeout`, `realpath`, `find`, `grep` и `xvfb-run` (если нет DISPLAY). Для 1С должны быть доступны системные библиотеки и шрифты.
3. В настройках репозитория **Settings → Secrets and variables → Actions → Variables** задать `ONEC_TRAINING_CI=true`. При необходимости добавить `ONEC_TRAINING_BIN=/полный/путь/к/1cv8t`; если `1cv8t` в `PATH`, переменная необязательна.
4. Получить `.dt` из Конфигуратора и положить в **`artifacts/warehouse.dt`**. Перед коммитом выполнить `git lfs install`, затем добавить и отправить файл.
5. Запушить в `main` или нажать **Actions → Verify 1C .dt with educational platform → Run workflow**.

До появления реальной `.dt` и настроенного runner CI будет **красным**. Если runner отсутствует после пройденного preflight, job останется в очереди и **не сможет стать зелёным**.

## Локальная проверка

```bash
export ONEC_TRAINING_BIN=/полный/путь/к/1cv8t
bash scripts/validate-dt.sh artifacts/warehouse.dt
```

Дополнительная среда `flake.nix` может использоваться локально для удобства разработки, но **не входит в обязательный GitHub CI**.

## Безопасность

- `.dt` — резервная копия информационной базы, включающая данные. **Не загружайте персональные данные** в публичный репозиторий: Git LFS не обеспечивает конфиденциальность.
- Не запускайте произвольные pull request на доверенном self-hosted runner. Поэтому реальная проверка настроена только для `main` и ручного запуска.
- Каждый этап ограничен по времени переменной `ONEC_TIMEOUT_SEC` (по умолчанию 900 секунд), сама job — 45 минут.
- Учебная версия 1С имеет ограничения использования. Запускайте CI на файловой базе с учебными данными.
