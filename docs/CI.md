# Минимальный CI для исходников 1С

**Цель:** проверить, что агент не запушил BSL-код с нарушениями синтаксиса. Для этого не требуется запускать платформу 1С или работать с `.dt`.

## Как работает

GitHub Actions (`.github/workflows/ci.yml`) запускается при push в `main`, Pull Request и вручную:

1. Убеждается, что в `src/` есть хотя бы один настоящий `.bsl` (до появления исходников CI **красный**, чтобы не изображать успешную проверку).
2. Устанавливает Java 21 и загружает официальный [BSL Language Server v1.0.7](https://github.com/1c-syntax/bsl-language-server/releases/tag/v1.0.7) с проверкой SHA-256.
3. Анализирует **все** `.bsl` внутри `src/` рекурсивно.
4. Скрипт `scripts/check-bsl-report.py` читает JSON-отчёт, проверяет, что все `.bsl` попали в анализ, и завершает job с ошибкой, если обнаружена диагностика `ParseError` (ошибка грамматики BSL / препроцессора).

Кроме этого, `scripts/check-metadata.py` проверяет XML-файлы, зарегистрированные объекты и связи между ними. Это **структурная XML-проверка**, не проверка импорта в платформу.

Остальные предупреждения о стиле кода **не блокируют** CI. Это намеренная минимальная настройка: строго проверяем синтаксис, а не форматирование и стандарты написания кода.

## Где писать исходники

Складывайте исходники из Конфигуратора 1С (XML и `.bsl`) в `src/`, например:

```text
src/
  CommonModules/
    Расчеты/Ext/Module.bsl
    Расчеты.xml
  Documents/
    РасходнаяНакладная/Ext/ObjectModule.bsl
    РасходнаяНакладная.xml
```

Пути примерные, фактическую структуру XML-выгрузки лучше сохранять такой, какой её создаёт 1С. Любое имя и глубина вложенности модулей `.bsl` подходят для проверки синтаксиса.

## Ограничения

- Это аналог синтаксической части `ruff check`: проверяет, что BSL-код разбирается парсером без `ParseError`.
- Это **не** гарантия, что конфигурация целиком собирается, что объекты метаданных существуют, что формы/накладные работают или что `.dt` открывается.
- Бинарный `.dt` используется для сдачи преподавателю. Проверка синтаксиса выполняется на XML + BSL исходниках, а не на `.dt`.
- Старые Nix/`validate-dt.sh` файлы, если остались в репозитории, в этом workflow **не участвуют**.

[Документация BSL Language Server](https://1c-syntax.github.io/bsl-language-server/), [диагностика ParseError](https://1c-syntax.github.io/bsl-language-server/diagnostics/ParseError/).
