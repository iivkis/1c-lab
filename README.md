# Тема №20. Контроль неснижаемого остатка товаров на складе

Учебная лабораторная работа на **1С:Предприятие 8.3**.

## Состояние проекта

**Этап 2: BSL-модули и черновая иерархия XML-метаданных — разработаны.**
Добавлены `Configuration.xml`, справочники, документы, регистры, обработки и подсистемы.
**XML ещё не проверен загрузкой в учебную платформу 1С.** Управляемые формы, макеты, СКД,
демонстрационная база и итоговая выгрузка `.dt` пока отсутствуют.

На текущем этапе подготовлены:

- логика прихода по накладной с движениями по остаткам и оборотам поставщиков;
- логика расхода с запретом записи/проведения ниже неснижаемого минимума;
- повторный контроль остатков внутри транзакции проведения с блокировкой регистра;
- суммирование повторяющихся строк товара;
- проверка отрицательного минимума в справочнике товаров;
- запросы для четырёх требуемых отчётов (пока **наборы данных, не готовые формы отчетов**);
- расчёты дополнительных задач №4, №12, №22, №26, а также **черновые управляемые формы** с полями ввода и кнопкой «Рассчитать» (интеграция в учебную 1С ещё не проверена).

## Структура

- `src/**/Ext/*.bsl` — модули объектов 1С; пути соответствуют именам из ТЗ.
- `docs/IMPLEMENTATION.md` — **точные требования к метаданным**, привязке модулей и тестам.
- `ФИНАЛЬНОЕ_ТЗ_1С_Тема_20_Контроль_неснижаемого_остатка.md` — исходное техническое задание.
- `.github/workflows/ci.yml` — синтаксический анализ каждого `.bsl` в `src/` через BSL Language Server.

## Правило склада

```text
КоличествоПосле = ТекущийОстатокНаВыбранномСкладе - СуммаРасходаПоТовару
Разрешить запись и проведение, только если КоличествоПосле >= МинимальныйОстаток.
```

Контроль проводится **до записи** и повторно **при проведении**. Вторая проверка работает
после записи движений с блокировкой регистра. Используются три регистра накопления, чтобы
четыре отчета брали данные только из регистров.

## Важно про CI

Зелёный CI означает, что **BSL-код синтаксически разбирается**. Он не гарантирует, что
метаданные собраны, объекты регистров существуют или конфигурация запускается. Полноценная
проверка возможна только после создания метаданных и импорта в учебную платформу 1С.

Следующий этап: управляемые формы накладных с автоподстановкой, печать, отчёты СКД, обмен и компонент анализа данных. После этого — проверка импорта XML в учебную 1С, приемочные тесты и выгрузка `.dt`.
