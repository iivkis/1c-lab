# Лабораторная работа №20: контроль неснижаемого остатка товаров на складе

Учебная конфигурация для **1С:Предприятие 8.3** (BSL + иерархический XML).
Финальное ТЗ: [ФИНАЛЬНОЕ_ТЗ_1С_Тема_20_Контроль_неснижаемого_остатка.md](ФИНАЛЬНОЕ_ТЗ_1С_Тема_20_Контроль_неснижаемого_остатка.md).

## Что реализовано в исходниках

| Часть | Содержимое |
|---|---|
| Справочники | **Товары**, **Склады**, **Поставщики**, **Получатели**; у товара реквизит `МинимальныйОстаток` |
| Документы | **ПриходнаяНакладная**, **РасходнаяНакладная**; формы и табличные части; расчёт итогов |
| Регистры | **ОстаткиТоваров**, **ПоступленияПоПоставщикам**, **ВыдачиПоПолучателям** |
| Контроль | Запрет записи/проведения ниже минимума, отдельные склады, учёт суммы повторных строк, повторная проверка при проведении |
| Формы | Автоподстановка доступного к отпуску, текущего остатка и минимума; пересчёт количества и прогноз остатка |
| Отчёты | Четыре отчёта **СКД**: контроль остатка, поступления поставщиков, выдачи получателям, диаграмма движения товаров |
| Печать и обмен | Команды **Печать** и **Экспорт в Excel (.xlsx)** в обеих накладных |
| Вычислительные задачи | Отдельные обработки с формами №4, №12, №22, №26 |
| Анализ данных | Обработка на основе встроенного `АнализДанных` (общая статистика склада) |
| Проверки | Обработка **Проверка лабораторной** с приёмочными сценариями и тестами четырёх задач |

`src/` содержит XML и BSL. GitHub Actions проверяет синтаксис BSL и структуру XML, но **не выполняет** платформенный импорт.

## Как проверить в настоящей учебной 1С

На Linux x86_64 с установленным учебным `1cv8t`:

```bash
export ONEC_TRAINING_BIN=/полный/путь/к/1cv8t
bash scripts/check-config-in-onec.sh
```

Создать постоянную базу для демонстрационных данных:

```bash
bash scripts/check-config-in-onec.sh --keep-db "$HOME/1c-warehouse-lab"
```

После проверки работы в режиме 1С:Предприятие и наполнения базы:

```bash
bash scripts/dump-demo-dt.sh "$HOME/1c-warehouse-lab"
```

Последняя команда создаёт `artifacts/warehouse.dt` для сдачи преподавателю.

**Статус:** исходники реализованы, но **интеграционная проверка загрузкой в учебную платформу не проводилась**. Итоговый `.dt` отсутствует. Зелёный CI не подтверждает запуск приложения или корректность метаданных на уровне платформы. Считать работу полностью сданной можно лишь после реального импорта, проверки сценариев и выгрузки `.dt`.
